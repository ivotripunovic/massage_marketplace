# Massage Marketplace — Database Schema

Schema for all current models, their relationships, constraints and indexes.
Generated by hand from `marketplace/*/models.py`; keep in sync when models change.

## 1. Entity relationships

```
                    ┌────────────────────┐
                    │     users_user     │  (custom AbstractUser)
                    ├────────────────────┤
                    │ id (PK)            │
                    │ email (UNIQUE)     │◄──────┐
                    │ password           │       │
                    │ first_name/last_name│      │
                    │ user_type          │       │ ONE-TO-ONE
                    │ is_email_verified  │       │
                    │ is_active/is_staff │       │
                    └────────────────────┘       │
                                                 ▼
                                    ┌──────────────────────────┐
                                    │    providers_provider    │
                                    │  (1 per user)            │
                                    └──────────────────────────┘
                                       │ 1                    │ 1        │ 1
              ┌────────────────────────┼──────────┬───────────┼──────────┼───────────┐
              │                        │          │           │          │           │
          1:1 ▼             1:1        ▼  1:N     ▼  1:N      ▼ 1:N      ▼ 1:N       ▼ 1:N
     providers_pricing   providers_  providers_  providers_  providers_ reviews_   payments_
                         gallery     attribute_  preference  custom_    review     subscription_
                         image       value       (per        preference            payment
                                                 subgroup)  (Other)
```

Location reference tables: `providers_continent` → `providers_country` → `providers_city`,
referenced from `providers_provider` (`country`, `city` FKs, `SET_NULL`).

Preference catalog: `providers_preference_group` → `providers_preference_subgroup`
→ `providers_preference_subgroup_option`; providers toggle subgroups via
`providers_provider_preference`, add free text via
`providers_preference_custom_option`, and define their own items via
`providers_custom_preference`.

Review catalog: `reviews_review` → `reviews_category_rating` (one row per
`reviews_category`) and an optional `reviews_reply`.

### 3.5 Preferences

**`providers_preference_group`**: `id`, `name` (UNIQUE, 150), `display_order`,
`is_active`.

**`providers_preference_subgroup`**: `id`, `group_id` FK → group CASCADE
(`subgroups`), `name` (150), `display_order`, `is_active`. Unique `(group, name)`.

**`providers_preference_subgroup_option`**: `id`, `subgroup_id` FK → subgroup
CASCADE (`options`), `text` (255), `display_order`.

**`providers_provider_preference`**: `id`, `provider_id` FK (`preferences`),
`subgroup_id` FK (`provider_preferences`), `is_checked`. Unique `(provider, subgroup)`.

**`providers_preference_custom_option`**: `id`, `provider_id` FK
(`preference_custom_options`), `subgroup_id` FK (`custom_options`), `text` (255),
`display_order`.

**`providers_custom_preference`**: `id`, `provider_id` FK (`custom_preferences`),
`name` (150), `display_order`.

The preference tree is cached under key `pref_groups_tree`; `providers/signals.py`
invalidates it on save/delete of group/subgroup/option models.

## 6. Integrity summary

- **Referential**: User→Provider cascades; Provider cascades to gallery, attributes,
  pricing, preferences, custom preferences, reviews, payments. Provider→Country/City
  is `SET_NULL`.
- **Unique**: `users_user.email`; `providers_provider.user_id`, `.slug`;
  `providers_city(name, country)`; `providers_attribute_value(provider, definition)`;
  `providers_preference_subgroup(group, name)`;
  `providers_provider_preference(provider, subgroup)`;
  `reviews_review(provider, client)`; `reviews_category_rating(review, category)`.
- **Validated**: review `comment` ≤ 250; category `rating` ∈ 1–5; reply `comment`
  ≤ 500; uploads type/size checked in forms.

## 7. Query patterns

```python
# Provider detail with related data
from providers.models import Provider
Provider.objects.select_related("user", "country", "city", "pricing").prefetch_related(
    "gallery_images",
    "attribute_values__definition",
    "preferences__subgroup",
)

# Provider with aggregate stats
from django.db.models import Count, Avg
Provider.objects.annotate(
    review_count=Count("reviews", distinct=True),
    avg_rating=Avg("reviews__category_ratings__rating"),
).get(slug=slug)

# Active providers only
Provider.objects.filter(subscription_status="active", user__is_email_verified=True)
```

Indexes worth noting: `subscription_status`, `(subscription_status, created_at)`,
city `(country, name)` / `(is_major_city)`, country `(continent, name)` /
`(is_active)`, `nowpayments_payment_id`, plus FK indexes.

## 9. Setup, backup & recovery

```bash
# Development (SQLite at marketplace/db.sqlite3)
python marketplace/manage.py migrate
python marketplace/manage.py createsuperuser

# Chained model changes — confirm no pending migrations
python marketplace/manage.py makemigrations --check --dry-run

# Backup / restore
python marketplace/manage.py dumpdata > backup.json
python marketplace/manage.py loaddata backup.json

# Reset (development only)
rm marketplace/db.sqlite3 && python marketplace/manage.py migrate
```

Production uses PostgreSQL; see [`DEPLOYMENT.md`](DEPLOYMENT.md) for backups.
